# PERSIAN PANEL — Railway Deploy (نسخه‌ی نهایی و تست‌شده)

پایه‌ی این دیپلوی، ایمیج رسمی [ghcr.io/mhsanaei/3x-ui](https://github.com/MHSanaei/3x-ui) هست —
همون پنلی که خودت داری استفاده می‌کنی. روی این ایمیج رسمی، یه لایه‌ی Nginx اضافه کردیم که
پنل، ساب‌اسکریپشن، و ۹ اسلات اینباند رو همزمان پشت یک پورت عمومی (همونی که Railway میده) در دسترس می‌ذاره.

**چرا ایمیج رسمی؟** چون طبق مستندات خودِ پروژه، در حالت Docker به‌صورت پیش‌فرض `admin`/`admin`
روی پورت `2053` بالا میاد — قابل‌اعتمادترین حالت ممکنه و نیازی به حدس زدن نداره.

---

## ۱) فورک / آپلود روی گیت‌هاب

یک ریپوی جدید (پیشنهاد: خصوصی) بساز و این ۴ فایل رو مستقیم توی ریشه‌ش آپلود کن:
`Dockerfile`، `nginx.conf.template`، `start.sh`، `railway.json`

## ۲) دیپلوی روی Railway

1. Railway → **New Project → Deploy from GitHub Repo** → ریپوت رو انتخاب کن
2. صبر کن Build تموم بشه (چند دقیقه — ایمیج پایه حجیمه)
3. **Settings → Regions** → **Europe West (Amsterdam)** رو انتخاب کن (نزدیک‌ترین ریجن به ایران)
4. **Settings → Networking** → **Generate Domain** بزن

## ۳) اولین ورود

`https://<دامنه‌ی-ریلوی>/` رو باز کن → `admin` / `admin` → فوراً از
**Panel Settings → Authentication** یوزر/پسورد رو عوض کن.

## ۴) ۹ اسلات اینباند — پورت و Path دقیق (این جدول رو دقیق رعایت کن)

| اسلات | پورت داخلی | Path (دقیقاً همین) |
|-------|-----------|---------------------|
| 1     | `8081`    | `/in1`              |
| 2     | `8082`    | `/in2`              |
| 3     | `8083`    | `/in3`              |
| 4     | `8084`    | `/in4`              |
| 5     | `8085`    | `/in5`              |
| 6     | `8086`    | `/in6`              |
| 7     | `8087`    | `/in7`              |
| 8     | `8088`    | `/in8`              |
| 9     | `8089`    | `/in9`              |

برای هرکدوم: **Inbounds → Add Inbound**
- Protocol: `VLESS`
- Network: `WebSocket` یا `XHTTP` یا `gRPC` (هرکدوم خواستی)
- Port: پورت داخلی همون اسلات (مثلاً `8085` برای اسلات ۵)
- Path: مقدار دقیق جدول (مثلاً `/in5`)
- Security: `none` (چون TLS رو خود Railway تأمین می‌کنه)
- بعد از ساخت، از داخلش **Add Client** بزن (UUID، Email، محدودیت حجم/تاریخ در صورت نیاز)

نیازی نیست هر ۹ تا رو پر کنی؛ ۲-۳ تا با ترنسپورت‌های مختلف کافیه.

## ۵) اینباند مستقیم روی پورت ۴۴۳ (بهترین پینگ)

1. توی پنل، اینباند VLESS + TCP + Reality رو روی یه پورت داخلی جدا بساز (مثلاً `9443`)
2. Railway → **Settings → Networking → TCP Proxy** → پورت داخلی `9443` رو اضافه کن
3. Railway یه `host:port` عمومی اختصاصی میده
4. توی همون اینباند، بخش **Hosts** پنل، فیلد Host/SNI رو با اون `host` (بدون پورت) تنظیم کن
5. توی کانفیگ کلاینت هم آدرس رو همون `host:port` بذار (نه دامنه‌ی اصلی)

## ۶) ساب‌اسکریپشن

**Panel Settings → Subscription**: پورت `2096`، Path `/sub`.
لینک نهایی: `https://<دامنه‌ی-ریلوی>/sub/<subId>` — همین رو توی v2rayNG/Streisand/Nekobox بده.

## ۷) (اختیاری) خروجی و مسیریابی برای لوکیشن دوم

اگه یه سرور دیگه (مثلاً ترکیه) در اختیار داری:
1. **Outbounds → Add Outbound** → آدرس/پورت/UUID اون سرور رو بزن
2. **Routing → Add Rule** → یکی از اینباندهای خودت (مثلاً اسلات ۵) رو به این خروجی وصل کن

نتیجه: کلاینتی که اسلات ۵ رو انتخاب کنه، ترافیکش از سرور دوم خارج می‌شه — یعنی از یک ساب، ۲ لوکیشن.

## چک‌لیست قبل از استفاده‌ی واقعی

- [ ] ریجن روی EU West (Amsterdam)
- [ ] حداقل ۲-۳ اینباند با پورت/Path دقیق از جدول بالا فعاله
- [ ] یوزر/پسورد پیش‌فرض عوض شده
- [ ] یه **Volume** روی `/etc/x-ui` وصله (وگرنه با هر دیپلوی جدید، کاربرها/تنظیمات پاک می‌شن)
- [ ] لینک ساب با هر سه اپراتور (همراه‌اول/ایرانسل/مخابرات) تست شده

## رفع مشکلات رایج

- **پنل بالا نمیاد / صفحه سفید:** Deployments → View Logs رو چک کن. معمولاً یعنی x-ui هنوز کامل بالا نیومده — چند ثانیه صبر کن و رفرش کن.
- **اینباند وصل نمی‌شه:** پورت/Path باید حرف‌به‌حرف با جدول بالا و `nginx.conf.template` یکی باشه.
- **بعد از هر دیپلوی، کاربرها پاک می‌شن:** Volume روی `/etc/x-ui` رو وصل کن.
- **پینگ روی یه اپراتور بد شد:** یعنی اون پروتکل خاص برای اون اپراتور اولویت نداره — کلاینت رو به اسلات دیگه سوییچ کن.
